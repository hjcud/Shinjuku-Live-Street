# 플레이어 정보 저장

VRChat SDK의 `VRC.SDK3.Persistence.PlayerData`를 사용한다. 외부 서버 없이 같은 월드 재방문 시 플레이어별로 복원한다.

## 저장 범위

모든 키에 `sjk.player.` 접두사를 붙인다. 사용자 요청 데이터는 다음 6개뿐이다.

| 키 | 타입 | 의미 |
| --- | --- | --- |
| vehicles | bool | 로컬 차량 표시 설정, 기본 true |
| ambient | bool | 로컬 환경음 설정, 기본 true |
| stayMinutes | int | 누적 체류 시간, 정수 분 |
| visitedDays | int | 방문한 날짜 수, 연속 방문 아님 |
| speakerMinutes | int | 본인 스피커 누적 사용 시간, 정수 분 |
| recordStartDay | int | 기록 시작 날짜, UTC+9 기준 날짜 번호 |

중복 방문 방지용 `lastVisitedDay`(int)와 저장 형식 버전 `schema`(int, 현재 2)만 내부 관리값으로 추가한다. 직접 반납 횟수·최초 스피커 설치·이미지 게시 여부·방문 장소·이동 경로는 기록하지 않는다.

## 시간과 날짜 기준

기록 시작 날짜는 로컬 PlayerData가 정상 복원된 뒤, 저장값이 없을 때만 해당 날짜로 초기화한다. 기존 이용자도 과거 방문 날짜나 누적 기록에서 첫 방문일을 추정하지 않고, 이 기능 적용 후 처음 복원한 날을 사용한다. 기존 누적 시간과 방문 날짜 수는 유지한다. 재접속·설정 변경·자정 통과·기기 시계 변경으로 시작 날짜를 갱신하지 않는다. 데이터 초기화 시에는 새로 기록한다.

`recordStartDay`는 기존 방문 날짜와 같은 `UTC+9 날짜의 Ticks / TimeSpan.TicksPerDay` 형식이며, 4바이트 int 하나다. 0은 미복원/미기록 상태이고 유효하지 않은 날짜 값은 복원 시 현재 날짜로 초기화한다. 표시할 때 `new DateTime((long)recordStartDay * TimeSpan.TicksPerDay)`로 변환할 수 있다. 이번 변경은 저장만 추가하며 날짜 표시 UI는 추가하지 않는다. 기존 키의 의미와 타입을 바꾸지 않는 추가 필드이므로 schema 2를 유지한다.

시간 측정은 `Time.realtimeSinceStartupAsDouble`로 하되 저장값은 4바이트 정수 분이다. 최대 2,147,483,647분(약 4,083년)에서 포화 처리하여 오버플로를 방지한다. 초 단위 double이 빠르게 넘치는 문제 때문이 아니라, 분 단위 정밀도로 충분한 데이터의 표현을 단순화한 것이다.

분 미만의 나머지는 접속 중 메모리에만 유지한다. 같은 접속에서 스피커를 35초 사용 후 반환하고 다시 25초 사용하면 1분이 된다. 반환 시 나머지를 초기화하지 않는다. 재접속하면 저장된 정수 분부터 시작하므로 이전 접속의 분 미만 나머지는 복원되지 않는다.

체류 시간에는 가만히 머문 시간도 포함한다. 스피커 시간은 본인의 실제 로컬 배치부터 반환 상태 적용까지이며, 실제 발화 시간은 아니다. 음성 내용·공연 여부·위치는 수집하지 않는다.

방문 날짜는 기기의 UTC 시계에 UTC+9를 적용한다. 같은 날 재접속은 추가하지 않고, 접속 중 자정을 넘기면 다음 저장 시 새 날짜를 추가한다. 연속 방문을 요구하지 않으며 방문하지 않은 날을 소급 집계하지 않는다. 시계가 뒤로 바뀌면 마지막 기록 날짜 이전의 날짜는 추가하지 않는다.

## 복원과 저장

로컬 플레이어의 `OnPlayerRestored` 이전에는 PlayerData를 덮어쓰지 않는다. 복원 전 활동은 메모리에 누적했다가 기존 저장값에 합산한다. 로딩 중 사용자가 바꾼 환경설정은 해당 항목에 한해 이전 저장값보다 우선한다. 원격 플레이어와 중복 복원 이벤트는 무시한다.

주기 타이머 하나가 30초마다 집계·저장한다. 설정 변경과 스피커 배치·반환 시에는 1초 지연으로 이벤트를 모아 저장한다. 정기 저장이 먼저 실행되면 중복 이벤트 저장은 생략한다. 추가 위치 검사·트리거·매 프레임 루프는 없다. 설정 적용은 본인 클라이언트에만 이루어진다.

퇴장하면 마지막 체크포인트 이후 시간과 저장하지 않은 분 미만 나머지가 누락될 수 있다. 서버 반영 지연이나 강제 종료 시 최종 저장까지 보장하지 않는다. 퇴장 이벤트 저장에 의존하지 않는다.

이전 schema 0/1의 초 단위 저장값이 있고 새 분 단위 키가 없다면 한 번 변환한다. 새 키가 있으면 항상 새 값을 우선한다. 과거의 추가 업적 키는 읽거나 갱신하지 않는다. PlayerData에는 개별 키 삭제 API가 없으므로 이미 서버에 기록된 과거 키를 이 코드가 삭제하지는 못한다. schema가 2보다 높으면 덮어쓰기를 막는다.

## 씬 연결

`Tools > Shinjuku > Connect player persistence`에서 현재 TEST 씬에 다음을 연결한다.

- 항상 활성인 World Player Data 오브젝트에 저장 컴포넌트 하나.
- WorldLocalSettings와 WorldPlayerData의 상호 참조.
- 모든 SpeakerController의 playerData 참조.
- 기존 두 지도 패널은 WorldLocalSettings를 통해 같은 설정을 표시한다.

이미지 로더에는 저장 이벤트나 참조를 연결하지 않는다. 이전 도구가 추가한 이미지 저장 참조와 폐기한 통계 필드는 씬 backing 데이터에서도 정리한다.

도구는 실제 UdonSharp 컴파일과 backing 참조를 검증한다. 기존 씬이 미저장 상태라면 백업과 연결 후 사본을 `output/player-persistence`에 저장하고 열린 원본 씬은 미저장 상태로 유지한다. 기존 작업과 함께 원본 TEST를 저장해야 변경이 원본 씬에 남는다. 처음부터 저장된 씬이면 원본을 저장한다.

## 전시용 씬 연결

`Tools > Shinjuku > Connect exhibition player persistence`는 `Assets/_ShinjukuExhibition/Scenes/TechnicalExhibition.unity`만 대상으로 한다. 일반 월드 씬은 다시 저장하지 않는다.

- 저장 컴포넌트 1개와 환경설정 컴포넌트 1개를 연결하고, 전시용 스피커 5개의 실제 배치·반환 이벤트를 기록한다.
- 기존 환경음 스위치를 유지하며 원래 제어 대상에서 추출한 AudioSource 19개만 설정에 연결한다. 전시용 미디어 제한 대상은 제외한다.
- 기존 환경음 스위치 옆에 같은 메시를 재사용한 차량 스위치를 추가한다. 음원이나 주변 장식은 복제하지 않는다.
- 차량 표시 전용 VehicleVisualPool만 숨기며 TrafficSimulationManager는 활성 상태를 유지한다.
- ObjectLocalToggle에 worldSettings가 지정된 두 스위치만 저장 가능한 설정에 동작을 위임한다. 연결하지 않은 다른 스위치는 기존 동작을 유지한다.
- 씬별 참조 외에는 같은 저장 코드·키를 사용한다. 실제 저장 범위는 VRChat의 월드 기준이므로 별도 월드로 업로드한 전시용과 일반 월드의 기록이 자동 합쳐지는 것은 아니다.

## 검증

- `output/player-persistence/RunTests.ps1`: 실제 저장·설정·스위치 소스를 테스트용 SDK 경계와 함께 컴파일하는 로직 테스트 26개. 기존 23개에 일반 스위치의 기존 동작 유지, 전시용 환경음 스위치 저장·복원, 차량 스위치의 표시 전용 제어를 추가했다.
- 씬 연결 도구: 실제 UdonSharp 컴파일, 단일 저장 컴포넌트, 설정·스피커 backing 참조, 복원 이벤트 엔트리 확인.
- 실제 클라우드 검증은 업로드된 월드에서 설정 OFF → 2분 이상 체류·스피커 사용 → 체크포인트 반영 후 재접속하여 설정·분 단위 기록·당일 날짜 중복 방지·기록 시작 날짜 유지를 확인해야 한다. 이 작업은 월드를 업로드하지 않는다.
